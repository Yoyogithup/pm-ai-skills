# 📙 开发指南

欢迎为 PM AI Skills 贡献你的技能！本文档介绍如何创建和贡献技能。

## 技能开发流程

### 1. 明确技能目标

回答以下问题：
- 这个技能解决什么问题？
- 目标用户是谁？
- 典型使用场景是什么？
- 期望的输出是什么？

### 2. 选择合适的分类

将技能归类到对应目录：
- `product-work/` - 产品工作相关
- `daily-life/` - 日常生活相关
- `project-management/` - 项目管理相关
- `fun-skills/` - 创意和趣味相关

### 3. 创建技能目录

```bash
cd skills/[分类名]/
mkdir your-skill-name
cd your-skill-name
```

### 4. 编写技能文件

创建 `skill.md`，参考模板：

```markdown
# 技能名称

> 一句话描述

## 功能说明

详细描述技能的功能...

## 使用方法

1. 步骤 1
2. 步骤 2
3. 步骤 3

## 示例

提供使用示例...

## 参数说明

如果有可配置参数，在此说明...
```

### 5. 编写 README

创建 `README.md`，包含：
- 功能介绍
- 主要特性
- 使用方法
- 输出示例
- 使用技巧

参考现有技能的 README 格式。

### 6. 测试技能

在本地测试技能：
1. 安装到 Claude Code
2. 测试各种使用场景
3. 确保输出符合预期
4. 优化提示和流程

### 7. 提交 PR

1. Fork 本仓库
2. 创建功能分支：`git checkout -b skill/your-skill-name`
3. 提交更改：`git commit -m 'Add: your-skill-name'`
4. 推送分支：`git push origin skill/your-skill-name`
5. 提交 Pull Request

## 技能开发规范

### 文件结构

```
your-skill-name/
├── skill.md          # 技能主文件（必需）
├── README.md         # 技能说明（必需）
└── examples/         # 使用示例（可选）
    └── example.md
```

### 命名规范

- **目录名**：小写字母 + 连字符，如 `prd-doc-writer`
- **文件名**：`skill.md`、`README.md`
- **技能名**：简洁明了，见名知意

### 文档规范

1. **清晰的标题结构** - 使用 Markdown 标题层级
2. **详细的使用说明** - 让新手也能快速上手
3. **丰富的示例** - 提供实际使用案例
4. **友好的排版** - 使用 emoji、表格、代码块等

### 代码规范

1. **注释清晰** - 关键步骤添加注释
2. **逻辑清晰** - 分步骤，易理解
3. **容错处理** - 考虑异常情况
4. **可配置** - 提供必要的参数配置

## 技能质量标准

### ✅ 好的技能特征

- 解决实际问题
- 使用流程清晰
- 输出质量高
- 文档完善
- 易于理解和使用

### ⚠️ 需要改进

- 功能不明确
- 使用复杂
- 输出质量不稳定
- 缺少文档
- 难以理解

## 贡献类型

除了新技能，你还可以贡献：

### 改进现有技能
- 优化提示词
- 补充使用示例
- 完善文档说明

### 修复 Bug
- 发现并修复技能问题
- 改进错误处理

### 完善文档
- 补充使用说明
- 添加最佳实践
- 翻译文档

## PR 提交规范

### 标题格式

```
类型: 简短描述

类型包括：
- Add: 新增技能
- Fix: 修复问题
- Improve: 改进优化
- Docs: 文档更新
```

### 描述内容

1. **背景** - 为什么要做这个改动？
2. **改动** - 具体做了什么？
3. **测试** - 如何验证这个改动？
4. **截图**（如果有）- 展示使用效果

### 示例

```
Add: 竞品分析助手

背景：
产品经理经常需要做竞品分析，但格式和内容不统一。

改动：
1. 新增 competitive-analysis 技能
2. 提供结构化的分析框架
3. 自动生成分析报告

测试：
- 已在本地测试多个竞品分析场景
- 输出格式符合预期
```
